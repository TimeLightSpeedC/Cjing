# 布局规范（跨平台统一）

> 目标：**同一宽高比在任何平台都得到同一套坐标**。
> 手机/平板/电脑、竖屏/横屏、自由窗口，全部由同一份 `core/src/layout.cpp` 计算。

---

## 一、为什么能统一

```
core/layout.cpp   ← 纯逻辑，不读窗口、不碰 SDL，只吃"逻辑宽高 + 安全区"
      ↑
platform_sdl/app.cpp  把窗口尺寸换算成逻辑画布（短边固定 900）
      ↑
Android / iOS / HarmonyOS / 桌面   共用同一份 app.cpp
```

平台差异只剩两个输入：**画布宽高比**与**安全区**。因此不存在"iOS 一套、鸿蒙一套"。

---

## 二、设计令牌

| 令牌 | 值 | 含义 |
|---|---|---|
| 逻辑短边 | **900** | 逻辑画布短边固定值，长边随窗口宽高比 |
| 棋盘占比（竖屏） | **88%** | 取 `min(可用宽, 可用高-预留)` 的 88% |
| 棋盘占比（宽屏） | **94%** | 宽屏高度是瓶颈，留白更小 |
| HUD 预留带 | **120** | 棋盘上方的文字区高度 |
| 状态行位置 | 预留带 **18%** | 距顶部 |
| 提示行位置 | 预留带 **58%** | 距顶部 |
| **行距** | **≈48** | 58%−18% × 120，**常量**，不随屏幕高度变化 |
| **提示到棋盘** | **≈51** | 120 − 58% × 120，**常量** |
| 宽屏 HUD 列宽 | **32%**（下限 240） | 右侧文字列 |
| 宽屏判定 | **宽 > 高 × 1.15** | 否则按竖屏 |
| 折行分隔符 | ` · ` | 长提示在宽屏下折成两行 |

> 历史问题：早期实现用「棋盘顶的 12% / 50%」定位 HUD，
> 屏幕越高、棋盘越靠下，两行就被拉得越开（手机上实测间距 236）。
> 改成「相对预留带」后成为常量。

## 三、各形态的预期结果

| 形态 | 逻辑画布 | 模式 | 棋盘 | HUD |
|---|---|---|---|---|
| 手机竖屏（iPhone 402×874） | 900×1956 | 竖屏 | 792 | 上方，提示单行 |
| 鸿蒙手机竖屏（1320×2031） | 900×1384 | 竖屏 | 792 | 上方，提示单行 |
| 平板竖屏（iPad 1032×1376） | 900×1200 | 竖屏 | 792 | 上方，提示单行 |
| 平板横屏（iPad 1376×1032） | 1200×900 | 宽屏 | ~771 | 右侧，提示两行 |
| 桌面宽屏（1600×900） | ~1600×900 | 宽屏 | ~840 | 右侧，提示两行 |
| 自由窗口（任意比例） | 短边 900 | 按比例 | 见公式 | 同上 |

## 四、回归保障

`core/tests/test_layout.cpp` 里有一组 `[spec]` 用例：

| 用例 | 钉住的约定 |
|---|---|
| 竖屏 HUD 行距与提示-棋盘间距为常量 | 48 / 51，且在 1200 / 1560 / 1956 三种高度下一致 |
| 宽屏棋盘至少占画布 55% 宽度 | 防止长文案把棋盘挤小（曾出现 420/1200 = 35%） |
| 各形态下棋盘正方形、不出界、HUD 在正确一侧 | 6 种形态矩阵 |

任何人改动布局参数，这组测试会先失败，避免"某个平台悄悄变形"。

## 六、桌面端是否也统一

是。桌面与移动端共用同一套布局与同一套令牌：

- 窗口接近正方形或竖长 → 竖屏排布（HUD 在上）
- 窗口明显偏宽 → 宽屏排布（棋盘靠左、HUD 在右）

调试方法：

```bash
CJING_WINDOW=1600x900 CJING_SHOT=/tmp/wide.bmp ./CjingApp   # 宽屏
CJING_WINDOW=800x1200 CJING_SHOT=/tmp/tall.bmp ./CjingApp   # 竖屏
```
